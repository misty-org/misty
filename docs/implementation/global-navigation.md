# Global navigation

This bounded extension uses the existing Misty visual system in `DESIGN.md` and the scoped Agents record in `src/features/agents/DESIGN.md`. Neither design file nor the design-token sidecar is regenerated. No new visual system or tokens are established.

The surface serves an operating task: open global destinations while keeping the current Space and its apps legible. The desktop navigator places Home, Discover, and Agents first, followed by Files and Browser as personal tools above a structural divider; the Space selector and apps sit below it. Search and Activity sit to the right of the content-width Misty server menu. Both dropdown triggers fit their contents within the rail and use 40px rows, 14px labels, and 24px identity slots, retaining prominence over the 18px navigation icons. The Misty logo renders as a contained image with a 1px inset to keep its edges clear. The Misty trigger uses the Space selector’s single-line label and inline chevron. Space avatars use rounded squares consistently, with a proportional 25% corner radius and an inheriting fallback. Agents is a global destination rather than a duplicate Space app row.

Home opens the global `/home` surface. Existing `/spaces/:spaceId/home` links remain valid Space destinations. The shell Space selector still changes workspace scope and opens that Space's remembered surface, falling back to its Space Home. It is distinct from the local selectors within global pages.

- Home labels its local selector **Agenda and app shortcuts**. It chooses the Space supplied to the existing dashboard; the agenda names that Space, while the page retains the user's Spaces overview. This does not promise an aggregated agenda or activity across Spaces.
- Agents retains a personal roster across Spaces. **Apps and work in** selects the Space used for app assignments and activity/work. Changing this local selection does not change the shell's Space selection.
- When the Agents editor has unsaved changes, choosing another local Space retains the current Space and draft and shows an inline alert. **Keep editing** cancels the pending switch. **Discard and switch** explicitly discards the draft and loads the selected Space context. The selector is disabled while the editor is busy. This guard describes the local Space selector, not every navigation action.

Evidence is the actual React components rendered in an isolated browser preview with synthetic data. The captures under `.impeccable/review/global-navigation/` are `desktop-home.png`, `desktop-agents.png`, `compact-agents.png`, and `unsaved-space-change.png`. They show the hierarchy, independent page filters, compact desktop layout, and retained draft alert. These are not native Tauri runtime captures and do not certify native window behavior, mobile layouts, live account integration, or backend permissions.

The account island contains Profile, Settings, and Help. It occupies a fixed-height footer in the navigator’s flex column; the app list and its scrollbar end 4px above the island instead of scrolling behind it. Help opens the existing tour, recovery, diagnostics, and feedback content in its own focus-managed dialog; it is no longer a Settings navigation entry. The desktop shell uses a 4px custom scrollbar with a thin fallback where WebKit scrollbar styling is unavailable. Titlebar action glyphs are reduced to 16px while retaining their existing button hit areas. Shell-control and Help previews are recorded under `.impeccable/review/shell-controls/`, also with synthetic data rather than native-runtime evidence.

The virtual-window menu separates rows with a 4px gap. Right-clicking a window offers Rename and Reset; account-scoped labels use the existing native navigation-name service at `~/.misty/config/navigation.json`. Renaming stays within the menu’s focus boundary. Reopening a closed window retains its label; clearing restore history removes closed-window labels while retaining open-window labels.

Files and Browser are always present as direct links in the personal-tools area, independently of Space app pins, and are excluded from the Space app picker and reorder list. They have no disclosure chevrons or nested sidebar destinations; their names and routes remain in use. Legacy pin/order records are filtered at render time rather than destructively rewritten. Opening either tool preserves the selected workspace Space. Their unscoped package routes continue to use the existing personal default-Space installation/session backing. Integration pages in Social, Planner, and other Space apps retain their owning-app placement. This changes navigation, not package permissions or persisted browser/file data.

Files provides a labeled Transfers button at the right of its Explorer toolbar, opening the existing `/apps/files?view=transfers` history. The global Files link returns to Explorer; its retained workspace remains mounted while transfer history is shown.

The global Files and Browser shortcuts do not grant installation or bundle their app packages. Desktop launch requires their separately downloaded package; embedded/hosted catalog fallbacks are rejected and opening a removed app offers Get app rather than silently reinstalling it. Production uses signed package installation; development may serve a separately built package from misty-apps. Files owns Explorer, previews, workspace state, and transfer presentation in its downloaded SDK component. The host no longer implements `fileSystem.mountWorkspace`; legacy packages receive an app-update error. Native filesystem and webview services, selection primitives, and global indexing remain shared host infrastructure. Desktop bundle validation rejects any rendered module from the Files or Browser package directories. Legacy bundled Files/Browser surfaces are retired on mobile too; this migration does not add a mobile download runtime.
