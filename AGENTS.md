# UI conventions

- Shared dropdown and context-menu selections use checkmarks, never dot indicators. Collection toolbars must not add a filter menu that duplicates their visible section tabs.
- Use the approved black, white and gray palette. Do not introduce green, sage, colored status dots, tinted selections or accent-colored focus rings unless the user explicitly requests color for that surface. Convey status through text and icons as well as contrast.
- Exception: item-type icon glyphs on content surfaces (the file explorer, and collection rows and cards on Spaces and other collection pages) use the shared tones in `src/shared/ui/icons/itemTones.ts`. Color the glyph only; icon tiles, hover, selection, focus and status stay monochrome. Tones mark what an item is, never its state. The app navbar, all sidebars (including the Extensions rail) and browser chrome stay uncolored. Add new kinds to the shared map rather than picking colors locally.
- Exception: tab groups use their chosen color: the filled label chip, the outlines of the group's tabs and the editor's swatches. Hover, focus and the rest of the tab strip stay monochrome, and a selected swatch shows a checkmark.
- Exception: virtual windows use their chosen color (`src/features/workspace/windowColors.ts`): a quiet wash over the window's chrome (the frame, navigator rail and tab strip) and the swatch in the window menu and picker. Page content, hover, focus and selection stay monochrome, and a selected swatch shows a checkmark. Every new window must be given a color first.
- Exception: official brand logos for connected apps (Integrations rows and tiles, and the app chips under the Agents composer) and for source browsers in the browser import flow (onboarding, Settings and the Bookmarks page) keep their original artwork via `BrandIcon` from `src/shared/ui/icons/brand-icons`. Never recolor them or hand-draw a substitute; apps without artwork fall back to a monochrome Lucide icon. Status around them stays text and icons.
- Exception: status dots on agent conversation rows (the Agents sidebar Recents) follow Claude's session list: gray at rest, pulsing while queued or working, amber when the run needs the user, red when it failed, using the `--misty-status-*` tokens in `src/styles/App.css`. A settled run's dot is filled until its conversation is read (on any device) and a hollow gray ring afterwards, meaning nothing new. Every dot keeps a text label (tooltip and screen reader). Do not spread status color to other surfaces.
- Exception: the night light (Settings › Appearance › Night light, `src/features/settings/store/nightLight.ts`) lays one warm multiply tint over the whole window and every browser page while it is on. It is off by default, the only setting that schedules anything visual, and the only place that warmth may appear. The theme itself stays Dark, Light or System.
- Exception: diffs (`src/features/agents/components/changes/`) tint added lines green and removed lines red, like Claude Code and Codex, with matching +/− counts. The tint marks the line's change, never state; file headers, buttons, selection and focus stay monochrome, and other surfaces don't borrow these colors.
- Never show "Loading…" or "Preparing …" text. First loads render animated skeletons shaped like the content that replaces them (`Skeleton`, `SkeletonList`, `SkeletonDocument`, `CollectionSkeleton` from `@/shared/ui`). Refreshes keep the current content on screen; never blank a surface or drop to a skeleton while revalidating.
- Preserve the existing settings sidebar geometry, Search field and Lucide icons. No group dividers, Account footer, nested disclosures, tab strips or chevrons on settings buttons (sidebar entries and rows alike). Each area opens a cohesive scrolling page with no title bar; plain section headers carry it.
- `src/features/settings/settingsRegistry.tsx` is the single settings navigation registry. Use `DesktopSettingsSection`, `DesktopSettingsRow` and `SettingsControls` for settings UI. Area names must not contain ampersands; each area has a unique icon.
- Settings pages are plain lists: no card boxes, hairlines between rows, every control right-aligned to one shared edge. Rows and sections carry a short muted line of helper text that explains what the setting does, its scope or its privacy and destructive consequences; keep it to a sentence or two and never repeat the label. Reset appears only while a value differs from its default and never moves the control. Up to four short choices use a segmented control; longer lists use a checkmarked dropdown, never a stack of radio buttons. Failures show as an inline notice in plain language, never raw setting keys or server errors.
- Settings belong to the device: they are saved in `misty.db` and never sync or reach the server. Do not add account-synced settings, outboxes, or "Settings sync" surfaces. Server-owned resources (conversation retention, hosted Misty, the model catalog) keep their own APIs and are not settings. Device identity and OS keychain secrets stay distinct from preferences.
- Approved Sync direction: `docs/design/sync/BRIEF.md`, revision 2, including the approved monochrome palette. Its server-account settings model is superseded: settings are device-local. Historical mockup screenshots do not override these instructions.
